## Что это

Утилита для сотрудников пункта выдачи Wildberries: слушает сканер
штрихкодов, делает снимок области экрана с номером ячейки в приложении
«Мой ПВЗ», распознаёт номер через OCR/ансамбль методов и сразу печатает
этикетку на термопринтере (протестировано на XP-370B, протокол TSPL).
Настройка — через локальный веб-интерфейс (иконка в трее). Есть портативная
сборка в один exe-файл для Windows, без установки Python отдельно.

## Обновление (портативная сборка exe со встроенным Tesseract и WebView2)

- **`build.bat`** — сборка одним двойным кликом (Windows): готовит
  виртуальное окружение, ставит зависимости, автоматически подтягивает
  портативный Tesseract OCR (через `winget` либо копированием уже
  установленного) в `assets/tesseract/`, скачивает крошечный (~2 МБ)
  официальный установщик Microsoft Edge WebView2 Runtime в
  `assets/webview2/` и собирает `pyinstaller build.spec`. Результат — один
  файл `dist/WB_PVZ_Printer.exe`, который переносится на любой Windows ПК и
  запускается без установки Python/Tesseract отдельно. Логика — в
  `build.ps1`, `.bat` только обходит политику PowerShell на запуск скриптов
  двойным кликом.
- `ocr.py` теперь сам находит встроенный портативный Tesseract рядом с
  собой (или внутри временной папки распаковки onefile-exe) и использует
  его в приоритете; если сборка портативного Tesseract отсутствует — тихо
  откатывается на системный Tesseract из `PATH`, как раньше.
- **`webview2_setup.py`** — при каждом запуске программы (до создания окна
  настроек) проверяет через реестр, установлен ли на этом ПК Microsoft Edge
  WebView2 Runtime (нужен `pywebview` для окна настроек); если нет — тихо
  запускает встроенный установщик (`assets/webview2/MicrosoftEdgeWebview2Setup.exe`,
  флаги `/silent /install`, официальный способ Microsoft). Для этого шага
  один раз нужен интернет на целевом ПК — сам установщик докачивает нужную
  версию с серверов Microsoft. На большинстве актуальных Windows 10/11
  WebView2 уже стоит из коробки, так что для них это тихий no-op. Если
  установить не удалось (нет интернета, установщик отсутствует в сборке) —
  программа не падает: `pywebview` на Windows автоматически откатывается на
  старый встроенный движок Internet Explorer/Trident, окно настроек всё
  равно откроется, просто без современной вёрстки (блюр из "Liquid Glass"),
  а `health_check.py` покажет об этом ненавязчивое предупреждение на
  дашборде (не блокирует работу).
- Подробности и ручные инструкции на случай, если что-то не подготовилось
  автоматически — раздел «Сборка в портативный exe» ниже.

## Обновление (пятый заход правок)

12. **Настройки распознавания разделены на "простое" и "расширенное"** —
    вкладка "Область распознавания" разрослась за 4 раунда правок до ~28
    полей, что рискует перегрузить оператора. Тонкая настройка OCR (порог,
    инверсия, ансамбль, эталоны) теперь свёрнута в `<details>` по умолчанию —
    видна только тем, кому реально нужно туда лезть.
13. **Сохранение пропорций при сравнении с эталонами цифр** — раньше вырезанный
    символ растягивался до фиксированного прямоугольника 24×32 без учёта
    пропорций (узкая "1" и широкая "8" приводились к одной и той же форме, что
    мешало сравнению). Теперь символ вписывается по большей стороне с
    сохранением пропорций и центрируется на белом поле — и при сохранении
    эталона на диск, и при сравнении используется одна и та же нормализация
    (`digit_templates._normalize_image`).
14. **Свои звуки через веб-интерфейс** — вкладка "Детектор сканера" → "Свои
    звуки": загрузка WAV-файла для каждого события (захват/успех/ошибка),
    кнопка "Прослушать" и "Сбросить на системный". Раньше это требовалось
    делать вручную, подкладывая файлы в `assets/sounds/` до сборки. Загруженные
    файлы хранятся в `%APPDATA%\WB_PVZ_Printer\sounds\` и имеют приоритет над
    встроенными. Только WAV — `winsound.PlaySound` не умеет MP3, при загрузке
    не-WAV файла сервер сразу отклоняет с понятным сообщением (проверка по
    заголовку RIFF/WAVE), а не молчит при первом реальном скане.

**Сознательно НЕ стали переделывать**: детектор сканера по таймингам клавиш
(альтернатива — Raw Input API с привязкой к конкретному устройству) обсудили
отдельно и решили не трогать — у пользователя настроены цветовые
точки-триггеры, которые гасят последствия возможного ложного срабатывания, а
риск пропуска настоящего скана в его условиях расценён как маловероятный.

## Обновление (четвёртый заход правок) — ансамбль распознавания и здоровье системы

8. **Посимвольная сегментация** — номер разбивается на отдельные символы по
   вертикальным просадкам яркости (`segmentation.py`) и каждый распознаётся
   отдельно (`--psm 10`), как ещё один "голос" в ансамбле наравне с
   распознаванием строки целиком.
9. **Самообучающиеся эталоны цифр** (`digit_templates.py`) — БЕЗ ручной
   калибровки: программа сама копит образцы каждой цифры из результатов с
   уверенностью ≥90% и согласием минимум 2 голосов в ансамбле, хранит до 5
   последних образцов на цифру и сравнивает новые распознавания с ними
   (нормализованная кросс-корреляция). Голосует, только когда для ВСЕХ цифр
   номера эталон уже "созрел" — иначе честно молчит, не гадает. Кнопка
   «Сбросить эталоны» — на вкладке «Область распознавания».
10. **OpenCV как ещё один голос** — адаптивная бинаризация по локальным окнам
    (`cv2.adaptiveThreshold`) + морфологическая чистка шума, пробуется на
    последней попытке ансамбля (баланс скорости/точности на слабом ПК).
    Опциональная зависимость — если OpenCV не установлен, просто не участвует.
11. **Проверка "здоровья" системы при старте** (`health_check.py`) — вместо
    отдельного окна-визарда: если есть критичная проблема (Tesseract не
    найден, нет прав на глобальный хук клавиатуры, pywebview не установлен) —
    окно настроек открывается СРАЗУ при старте с блокирующей модалкой,
    которую нельзя закрыть, пока проблема не решена. Некритичные предупреждения
    (принтер не выбран, область не откалибрована) — ненавязчивый закрываемый
    баннер на дашборде.

**Компромисс по производительности** (обсуждён с пользователем, слабый ПК на
ПВЗ): тяжёлые нейросетевые OCR (EasyOCR/PaddleOCR) сознательно НЕ
использовались — только лёгкие классические методы (Tesseract, OpenCV classic
CV, сравнение с эталонами через numpy). OpenCV-вариант выполняется только раз
за цикл распознавания (не на каждой попытке), чтобы не множить нагрузку.

**Новая зависимость**: `opencv-python-headless` + `numpy` (~30-60 МБ к
установщику) — если это неприемлемо, выключите галку «Адаптивная бинаризация
через OpenCV» в настройках, остальной ансамбль (сегментация + эталоны)
работает и без неё.

## Обновление (третий заход правок)

7. **Инверсия цвета на печати** (фон чёрный/текст белый вместо наоборот) —
   подтверждённая на реальном принтере пользователя проблема полярности битов
   в TSPL `BITMAP`. Настройка `printer.bitmap_invert` теперь **включена по
   умолчанию** для новых установок. Если у вас уже стоит программа и
   `config.json` был создан раньше — зайдите на вкладку «Принтер», включите
   галку «Инвертировать битмап (если текст/картинка печатаются в негативе)»
   и нажмите «Сохранить» (менять код/переустанавливать не нужно — это
   единственное действие). Затрагивает номер ячейки, произвольный текст и
   загруженную картинку — рисуются как растровые BITMAP; полоса-ориентир (BAR)
   печатается отдельной TSPL-командой и этой проблемы не имеет.

## Обновление (второй заход правок)

По фидбэку после первой версии внесены следующие изменения:

1. **Журнал печати** — левое меню больше не растягивается и не скроллится вместе
   со страницей (зафиксирована высота `.sidebar`/`.content` = 100vh). Внутри
   вкладки «Журнал печати» скроллится только сама таблица (`.log-table-wrap`,
   `max-height: 62vh`), тулбар с фильтрами остаётся на месте. Добавлена кнопка
   «Очистить журнал» (с подтверждением), фильтры по статусу/номеру, экспорт в CSV.
2. **Баг калибровки** — при повторном выделении области старый прямоугольник
   больше не оставался на скриншоте: перед началом нового выделения теперь явно
   удаляются все `.select-rect` из области (см. `app.js: setupSelectionDrag`).
3. **Цветовые точки-триггеры** — доп. проверка перед печатью: печать выполняется,
   только если в заданных точках экрана (свои X/Y, отдельно от области номера)
   присутствует нужный цвет (пипетка — клик по тому же скриншоту калибровки).
   Допуск — в процентах на канал. Несколько точек с логикой И/ИЛИ. Если цвет не
   совпал сразу после скана — печать ТИХО отменяется (без сигнала ошибки),
   событие пишется в журнал нейтральной пометкой «Пропущено» (см. `color_trigger.py`).
4. **Автоцентровка и автоподбор размера текста** — номер ячейки и произвольный
   текст в редакторе макета задаются теперь ПРЯМОУГОЛЬНИКОМ (как полоса/картинка):
   при печати текст автоматически центрируется внутри рамки и подбирается
   максимальный размер шрифта, вписывающийся в неё. Это же чинит баг «печатает
   всегда мелкий номер, размер не меняется» — причина была в том, что TSPL-команда
   `TEXT` печаталась через дискретные встроенные битмап-шрифты принтера с
   множителем x_mult/y_mult=1 всегда, размер из настроек нигде не использовался.
   Теперь номер/текст рендерятся через PIL с фиксированным TTF-шрифтом (DejaVu Sans,
   свободная лицензия, лежит в `assets/fonts/`) в растровое изображение нужного
   размера и отправляются как TSPL `BITMAP` — это даёт точный контроль размера
   на любой рамке (см. `printer_tspl.py: render_autofit_text_bitmap`).
5. **Качество OCR** — распознавание теперь настраиваемое (увеличение, порог
   бинаризации авто/ручной, инверсия авто/принудительно) и оценивает уверенность
   через `pytesseract.image_to_data`; повторные попытки варьируют параметры и
   выбирают лучший результат голосованием, а не "первый попавшийся". Кнопка
   «Проверить область» показывает % уверенности и обработанную картинку — по ней
   удобно подбирать параметры вручную, если распознаётся неправильно.
6. **Доп. функции**: глобальные горячие клавиши (пауза/повтор печати/открыть
   настройки — `hotkeys.py`), кнопка «Тестовый скан» (прогон всего цикла без
   физического сканера), превью откалиброванных областей на дашборде, фильтры и
   CSV-экспорт журнала, вкладка «Инструкция» с пошаговым гайдом.

**Не проверялось на реальном Windows-железе** (сборка велась в Linux-песочнице):
сама отрисовка BITMAP была визуально проверена (см. `/tmp/preview_*.png` в ходе
разработки — рендер текста в рамку выглядит корректно), но полярность бит,
реальный размер на этикетке и точность OCR на настоящем шрифте «Мой ПВЗ» нужно
проверить на месте и при необходимости подстроить `printer.bitmap_invert` и
параметры OCR через UI.

## Риски и альтернативы (как и просили — до начала кодирования)

### 1. Детектор сканера (тайминги клавиш)
Реализовано по рекомендованному в ТЗ стеку: глобальный хук `keyboard`,
эвристика по интервалам между символами + `Enter`. Это самый простой и
рекомендованный ТЗ вариант.

**Альтернатива**: Raw Input API (`WM_INPUT`) с фильтрацией по device handle —
физически отделяет ввод сканера от ввода обычной клавиатуры, полностью
исключая теоретическую возможность ложного срабатывания на быстрый ручной
ввод. Минусы — сложнее реализация (Win32 message loop через ctypes/pywin32),
сложнее отлаживать. Не реализовано в этой версии (выбран вариант по
умолчанию из ТЗ); при необходимости можно добавить отдельным модулем,
не трогая остальную архитектуру — интерфейс `ScannerListener` уже
абстрагирован под замену реализации.

### 2. Точность OCR
Реализовано: `pytesseract` + upscale в 4 раза + бинаризация + whitelist
цифр + `--psm 7`. Должно неплохо работать на чётком системном шрифте, но
общей гарантии 100%-й точности OCR дать невозможно.

**Альтернатива**: распознавание по шаблонам цифр (template matching) —
поскольку шрифт в «Мой ПВЗ» фиксированный, можно один раз «обучить» программу
эталонным изображениям цифр 0–9 (снять их при калибровке) и затем сравнивать
сегменты изображения с эталонами вместо общего OCR. Даёт почти 100% точность
для фиксированного шрифта, но не реализовано в этой версии — если на практике
`pytesseract` будет ошибаться чаще, чем приемлемо, это первое, что стоит
сделать (потребует переписать только `ocr.py`, остальной пайплайн не
меняется).

### 3. Полярность бит в TSPL BITMAP
Bit=1 в реализации означает «печатать чёрную точку». Если на реальном
принтере картинка выйдет в негативе — включите
`printer.bitmap_invert` в настройках (вкладка «Принтер»), код менять не надо.

## Установка и первый запуск (для разработки/тестирования)

1. Установите Python 3.11+ (Windows).
2. Установите Tesseract OCR для Windows:
   https://github.com/UB-Mannheim/tesseract/wiki — после установки либо
   добавьте путь к `tesseract.exe` в PATH, либо укажите его явно в начале
   `ocr.py` через `pytesseract.pytesseract.tesseract_cmd = r"C:\...\tesseract.exe"`.
3. В папке проекта:
   ```
   pip install -r requirements.txt
   ```
4. Для pywin32 иногда нужно однократно выполнить пост-установочный скрипт:
   ```
   python Scripts\pywin32_postinstall.py -install
   ```
5. Запуск:
   ```
   python main.py
   ```
   Появится иконка в системном трее (фиолетовый круг WB). Клик правой
   кнопкой → «Открыть настройки».

## Первичная настройка через UI

1. Вкладка **«Принтер»** — выберите XP-370B из списка, укажите размер
   этикетки/DPI, нажмите «Тестовая печать» с произвольным номером — убедитесь,
   что печать физически работает (это шаг 2 из раздела 7 ТЗ).
2. Вкладка **«Область распознавания»** — укажите точный заголовок окна «Мой
   ПВЗ» (если отличается от значения по умолчанию), нажмите «Откалибровать»,
   переключитесь на окно «Мой ПВЗ», дождитесь снимка, выделите мышкой
   прямоугольник вокруг номера ячейки, сохраните. Проверьте кнопкой
   «Захватить и распознать сейчас».
3. Вкладка **«Детектор сканера»** — подстройте тайминги под конкретную модель
   сканера, если стандартные 40 мс не подходят (некоторые дешёвые сканеры
   эмулируют клавиатуру медленнее).
4. Вкладка **«Редактор этикетки»** — перетаскиванием разместите номер ячейки,
   полосу, статичный текст (например, название ПВЗ) и картинку/логотип.
5. Проверьте полный цикл реальным сканированием товара.

## Сборка в портативный exe (единый файл, Python + Tesseract + WebView2 внутри)

**Самый простой способ** — дважды кликнуть `build.bat` (запускать на
Windows). Скрипт сам:
1. проверит Python и создаст изолированное `build_venv`;
2. установит зависимости из `requirements.txt` и `pyinstaller`;
3. если Tesseract ещё не подготовлен — попробует поставить его через
   `winget` (пакет `UB-Mannheim.TesseractOCR`) или найдёт уже установленный
   и скопирует нужные файлы (exe + dll + `tessdata/eng.traineddata`,
   `osd.traineddata`) в `assets/tesseract/`;
4. если установщик WebView2 ещё не подготовлен — скачает официальный
   Evergreen Bootstrapper (~2 МБ) в `assets/webview2/`;
5. запустит `pyinstaller build.spec --clean --noconfirm`.

На выходе — **один файл** `dist/WB_PVZ_Printer.exe` (~120-180 МБ, зависит от
версии Tesseract), который можно скопировать на любой Windows ПК и просто
запустить: Python, все библиотеки, Tesseract и установщик WebView2 уже
внутри, ничего отдельно ставить не нужно.

- `ocr.py` при старте сам находит встроенный Tesseract
  (`assets/tesseract/tesseract.exe`, распаковывается PyInstaller во временную
  `sys._MEIPASS` при каждом запуске) — если его там нет, тихо откатывается на
  системный Tesseract из `PATH`, как раньше.
- `main.py` при старте (до создания окна) вызывает
  `webview2_setup.ensure_installed()` — если на ПК ещё нет Microsoft Edge
  WebView2 Runtime, он тихо ставится из встроенного установщика (нужен
  интернет на этом ПК один раз). Если WebView2 всё же недоступен (нет
  интернета, установщик отсутствует в сборке) — программа не падает, просто
  окно настроек откроется на старом движке (без современной вёрстки), а
  `health_check.py` покажет предупреждение на дашборде.

Если Tesseract или установщик WebView2 не удалось подготовить автоматически
(например, нет `winget` или нет интернета на машине, где собираете exe),
скрипт объяснит, что сделать вручную, и что можно продолжить без них — не
критично для самой сборки.

**Вручную, шаг за шагом** (если нужен контроль над процессом или сборка не с
Windows-машины с `build.bat`):
```
pip install -r requirements.txt
pip install pyinstaller==6.10.0
REM подготовьте assets/tesseract/tesseract.exe заранее (скопируйте туда
REM папку установленного Tesseract-OCR) — иначе распознавание не заработает
REM опционально: положите assets/webview2/MicrosoftEdgeWebview2Setup.exe
REM (Evergreen Bootstrapper с https://developer.microsoft.com/microsoft-edge/webview2/)
pyinstaller build.spec --clean --noconfirm
```
`web_ui/static` и вся папка `assets` (включая `assets/tesseract` и
`assets/webview2`, если подготовлены) включены в сборку через `datas` в
`build.spec`.

## Структура проекта

```
main.py              — точка входа, связывает всё воедино
config.py             — настройки: дефолты, загрузка/сохранение, экспорт/импорт
engine.py              — центральный пайплайн: скан → задержка → захват → OCR → печать
scanner_listener.py    — детектор сканера по таймингам клавиш
screen_capture.py      — поиск окна «Мой ПВЗ» и захват области экрана
ocr.py                 — распознавание номера ячейки
printer_tspl.py        — сборка TSPL-команд и сырая печать через win32print
sound.py               — звуковые сигналы (winsound)
tray.py                — иконка в системном трее
autostart.py           — автозапуск через реестр HKCU\...\Run
print_log.py           — журнал печати для UI
logger_setup.py        — логирование ошибок в файл
web_ui/server.py        — Flask backend локального веб-UI
web_ui/static/          — фронтенд (HTML/CSS/JS, без сборки и внешних CDN)
build.spec              — сборка в exe через PyInstaller
```

Конфигурация и логи хранятся в `%APPDATA%\WB_PVZ_Printer\`
(`config.json`, `print_log.json`, `logs\app.log`, `images\`).

## Известные допущения (см. также комментарии в коде)

- Заголовок окна ищется по вхождению подстроки, а не по точному совпадению
  (переключается галочкой «Точное совпадение заголовка»).
- Звук по умолчанию — системный `winsound.Beep` (нельзя приглушить
  программно); для более мягкого звука положите свои `.wav` в
  `assets/sounds/{capture,success,error}.wav`.
- При ошибке «окно не найдено» звуковой сигнал ошибки НЕ проигрывается
  (по ТЗ п.3.3 это привязано именно к неудаче OCR после всех попыток) —
  статус в трее при этом всё равно становится красным.
- Drag-and-drop редактор реализован на чистом JS (без Fabric.js/interact.js),
  чтобы приложение оставалось полностью автономным и не требовало интернета
  при запуске в ПВЗ.
